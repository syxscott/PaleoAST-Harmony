# 分析历史去重会吞掉真实运行:载入不同数据、参数相同的那次运行不落库

## 类型
缺陷修复

## 问题

`HistoryRepository.insertRecord` 在插入前会做一次去重探针,命中已有记录就跳过,
以免同一个分析被反复记录。它比较的键是 `params` 的字符串形式。

而 `params` 里装的是**对话框参数**(method、距离度量、置换次数……),
**不含数据本身**。于是下面这个序列会静默丢数据:

1. 载入数据集 A,跑一次 `PERMANOVA`(参数 `{'permutations': 999}`)→ 落库。
2. 换一份数据 B(行数、列数完全一样),再跑一次 `PERMANOVA`,参数一字未改
   → 去重探针判定"与已有记录相同",**这次运行既不出现在历史里,也不出现在导出的可复现脚本里**。

用户在历史上看不到自己跑过什么,导出的脚本也无法重放第 2 次运行。
而"没跑过"和"跑了但被静默丢弃"在界面上完全一样。

## 根因

去重的**意图**(同一份数据 + 同一组参数不该刷屏)是合理的,
实现**(只比较参数)与意图不匹配**。参数相同的两次运行在语义上是不同的,
因为它们作用在不同数据上。

顺带一提,仓库里已经有 `data_shape()` 能识别"行列数 + 行列标签",
但它对两个同形状、不同数值的数据集(48x12 矩阵 vs 另一个 48x12 矩阵)是无法区分的,
所以它也不足以充当去重键。

## 修复

给去重键补上**数据指纹**,而不是删掉去重。

1. 新增 `entry/src/main/ets/utils/dataFingerprint.ts`:
   FNV-1a 哈希,输入是数据值的**原始 IEEE-754 字节**加行列标签。
   导出常量 `DATA_HASH_KEY = '_dataHash'`。
2. `Index.ets`:
   - `persistAnalysis` 把指纹打进**存库用**的 params(`storedParams`);
   - `recordAnalysis` 推进内存 `analysisHistory` 的仍是调用方原始 params,
     所以 `buildAnalysisScript`(可复现脚本的唯一数据源)永远不会泄漏这个内部键;
   - `restoreHistory` 从库里解析回来后 `delete params[DATA_HASH_KEY]`;
     旧记录没有该键也能正常解析(解析本身有 try/catch 兜底)。
3. **没有给 `history` 表加列** —— `CREATE TABLE IF NOT EXISTS` 对已存在的库不会补列,
   那样升级后会直接崩。指纹寄生在 params JSON 里,天然向后兼容。

## 验证

新增 `tests/history2026.test.ts`,10 条回归测试,测试名一律描述旧行为。

指纹的 10 条性质:

- 同一份数据永远得到同一指纹;
- **一个单元格的分数变化会改变指纹** —— 包括 `4` 与 `4.5` 这种差异;
- 两个 `data_shape()` 无法区分的同形状数据集指纹不同;
- 标签变更会改变指纹,NaN 稳定;
- 没有数据集的哈希会撞上 "none" 哨兵值,`null` 也一样。

脚本侧的 4 条:`persistAnalysis` 只在**存库**的 params 上盖戳;
内存历史(脚本的唯一来源)保持原样;`restoreHistory` 会再次剥掉它,
且没有该键的旧记录照样解析;保留键名由模块导出,两端不会各自写字符串而漂移。

**指纹第一版有 bug,被自己的验证抓住**:我先用 `mix(v) = v & 0xff` 混合,
位运算会截断小数,导致 `4` 与 `4.5`、`58` 与 `58.5` 哈希相同 ——
即"分数变化会改变指纹"这条测试失败。改为直接哈希 `Uint8Array` 的原始字节后,
10 条性质全过(包含 1e-12 量级的差异)。

性能:48x12 约 0.04ms,5000x60(2.4MB)约 20.6ms。

门禁:`tests/test.mjs` **212 passed, 0 failed**;`node test/device/run.mjs` 19/19;
`structure_check.py` 175 文件 0 问题。未跑 DevEco 构建(只动 `ets/**` 与 `tests/**`)。

## 风险

- 指纹只覆盖**进入分析的那个 `DataMatrix`**,不覆盖对话框之外的环境
  (例如 RNG 状态、全局设置)。这两者目前都不影响去重语义。
- 用户若在同一个 Session 内改数据后立刻重跑,历史里会出现一条与旧记录
  "参数一样、指纹不同"的记录 —— 这正是期望行为。
